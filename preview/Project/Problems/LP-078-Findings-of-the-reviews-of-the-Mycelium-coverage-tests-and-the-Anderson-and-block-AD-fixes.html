Mistral: the Anderson and block AD fixes

The fixes (Codex): Anderson fits its coefficients to the primal residuals and mixes the dual messages (LP-053 finding 2); GaussianBlock, ComponentMixtureBlock and belief_block build under Zygote (LP-044 finding 1). Mistral checked, with scripts, that float runs are bitwise those of the old code in 48 settings, that unmixable messages leave the sweep to the inner schedule, that the blocks copy their inputs and give Zygote’s gradient equal to ForwardDiff’s, and that duals of two tags nest.

#findingright?donetest
M1A float run on a store that holds the dual messages of an earlier run writes duals into every mixed edge, and takes 42 sweeps where the old code took 90the observation is right (reproduced with probe4c.jl); not a defect of the change. The inner sweep reads the stale dual messages, so the float run’s factors carry their tangents on under any schedule: the old code left 15 of 18 messages dual too, it only did not mix them. A rule that took the run’s element type from the rewritten messages did not change that (tried, a bitwise oracle failed for the same reason) and was droppedrecorded in anderson.md (“One store, dual and float runs”): use a fresh store for a float run after a dual one—
M2Under duals the sweep count can differ from the float run’s by far more than one: around flooding_schedule, 1193 against 949, and 849 against 888 at source 104yes: the notes claimed agreement within one sweep in general. The derivatives match the dense solve in every case (within 4.4⋅10−13)anderson.md and passing.md corrected: the agreement holds around the spanning-tree schedule—
