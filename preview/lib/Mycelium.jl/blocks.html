blocks

03 Nov 202612 min read

  • implementation

implementation

Message blocks: the store holds the messages of one template edge of a plate, for all replicas, as one value, and a plate sweep reads and writes whole blocks; any other reader indexes an edge as before and gets its column. With the factor-analysis plate on blocks a sweep is about 9 times the hand-written E-step instead of about 240 times, and the free energy and its gradient over a plate are one call per template factor (bench/plates.jl).

Sources: original to this repository (decision: L-ADR-0010 Plates get batched message blocks). code: blocks.jl, messages.jl (MessageStore), plates.jl (_step_blocks!, _step_cavity!), passing.jl (factor_messages on blocks), free_energy.jl (local_free_energies, factor_beliefs, belief_free_energies), factors.jl (DataFactor), ../../../src/constraint.jl, ../../../src/gaussian.jl; tests: ../../../test/plates.jl; benchmark: ../../../bench/plates.jl

Theory (CT-ML wiki): Variational Free Energy

Implements: L-SPEC-006 Plates §5–§6.

Blocks

A BeliefBlock is n beliefs of one kind:

blockholdscolumn i
TrivialBlock(n)nothingTrivialBelief()
PointBlock(X)X∈Rd×nDiracBelief(X[:, i])
GaussianBlock(η, Λ, improper)η∈Rd×n; Λ shared (d×d) or a vector of nGaussianBelief(η[:, i], Λᵢ, improper[i])
CategoricalBlock(logp, labels)logp∈RK×n, columns normalisedCategoricalBelief(logp[:, i])
MixtureBlock(η, Λ, logw, improper)η∈Rd×K×n, one Λ for every component, logw∈RK×nMixtureBelief of GaussianBelief(η[:, k, i], Λ, improper)
VectorBlock(beliefs)anythingbeliefs[i]

belief_block(beliefs) picks the most specific block for a vector of beliefs, keeping a precision shared when every belief holds the same precision object. That sharing is the point. In a plate of tied factors with data as points, every replica’s message has the same precision (the prior’s, or KAt​ of a tied linear factor), so the block is one d×n matrix and one d×d one.

The operations a sweep needs work column for column, just as the per-belief rules do:

  • combine_blocks: Gaussian blocks add canonical parameters (shared plus shared stays shared), a point dominates a Gaussian, the trivial block is the unit, and the improper flag follows combine on each column. Any other pair is combined column by column with combine, with its errors.
  • Categorical blocks multiply column by column (log-probabilities add, each column normalised); block_distance is the largest total variation, and the entropies of a variable row are one vectorised sum.
  • A mixture block times a Gaussian block of one proper shared precision, in either order, is the componentwise product of _mixture_product with its overlaps, batched (_mixture_gaussian): proper components through the convolution form of _overlap, improper ones through its expansion about the Gaussian’s mean, one factorisation for all Kn pairs. With K=1 a re-centring point can enter, so that, and any other pair, goes column by column.
  • block_distance: the largest belief_distance over the columns (max(∥Δη∥∞​,∥ΔΛ∥∞​) for Gaussians, the norm of the difference for points), without temporaries.

The store

MessageStore’s two directions are EdgeMessages, an AbstractVector{Any} that indexes like the Vector{Any} it replaced. MessageStore(g) gives each template edge of each plate a block row (the edges pl.edges[k, :], replica i in column i). A row either holds one Message whose belief is a block, or its edges hold their own messages:

  • s.to_variable[e] for an edge of a row held as a block returns Message(replica(block, i), iteration), a view built on demand. Marginals, the free energy, both gradient drivers, the sampler and the tests read edges this way and did not change.
  • s.to_variable[e] = m on such an edge first writes every column back as an edge message (_unblock!), so a per-edge write never mixes with a stale block.
  • fill! (used by reset!) clears both. copy returns a plain Vector{Any} of the views, and a store built from vectors (MessageStore(tv, tf, iteration), as the coupled drivers do) has no rows, so every block path is skipped for it.

Sweeps on blocks

plate_schedule records, per lifted group, the block row of each channel’s edges (_GroupPlan.rows), and for a group of variable → factor messages a _CavityPlan: the rows of the other edges at each member’s variable, in the same order for every member.

  • factor → variable (_step_blocks!): the inputs are the rows’ blocks (a row filled edge by edge is gathered into a block). The call is factor_messages(factors, target, polarity, inputs::NamedTuple, priors, ps, st), which returns one block, and the block is written to the target row. The default method takes each column and calls the per-replica factor_messages, so a factor without block arithmetic still works. With damping or a detached target edge the result is committed edge by edge.
  • variable → factor (_step_cavity!): the excluded marginal of every member is combine_blocks over the other rows, one block operation per row.

When a variable is pinned, an input row is partly filled, or a row is uninformative in some columns only, the group takes the per-edge path of before. The tests check that a grouped sweep still gives the sequential schedule’s messages to 10−12, and that after a sweep of the factor-analysis plate all six live rows are blocks: four Gaussian blocks with a shared precision and two point blocks.

Batched methods: LinearConstraintFactor (inputs as points, trivial, or proper Gaussians with one shared precision: one factorisation, then H=Kc1⊤−∑n​(KAn​)Mn​), GaussianPrior (one conversion when the replicas share mean and covariance), DataFactor (the data as one point block), and SwitchingConstraintFactor to its outcome (the same inputs as the linear factor: one metric, then logPi​(k)=logwk​−21​∥T(bk​−si​)∥2 as a CategoricalBlock; 2026-11-03, switching.md §10).

Energies on blocks

A plate factor row whose messages are blocks (belief-propagation nodes on one key, edges in rows, none detached) is evaluated by three hooks. Each defaults to a loop over replicas:

  • local_free_energies(factors, msgs, ps, st): every replica’s local free energy, used by factor_free_energies and scalar_free_energy;
  • factor_beliefs(factors, msgs, ps, st), outside AD, and belief_free_energies(factors, beliefs, ps, st), differentiable in ps: the parameter gradient’s frozen beliefs and its energies (LP-020). free_energy_gradient differentiates one item per row instead of n.

SwitchingConstraintFactor implements them through FrozenSwitchingBeliefs (one precision, covariance and H(x∣k), a mean per outcome and replica, the outcome posteriors as a K×n matrix; switching.md §10). LinearConstraintFactor and GaussianPrior implement them through FrozenGaussianBeliefs (in Lenticulum’s gaussian.jl): with every free input a Gaussian block of shared precision, the factor beliefs share one covariance and entropy, and only the means differ, one column each. The variable terms of the Bethe free energy go by rows as well: the marginal block of a variable row and its entropies, one entropy evaluation for a shared precision.

test/plates.jl compares a store with blocks against the same messages held edge by edge (a store built from the copied vectors): the scalar free energy agrees to 10−13 (relative), each factor’s graded terms to 10−12, and the gradient of the tied entry to 10−10 with ForwardDiff and Zygote (10−6 with reference differences, whose step is 10−6).

Mixture blocks and EP on blocks (2026-11-03)

A plate of tied switching factors sends its mixture messages to a continuous channel as one MixtureBlock when the inputs are as for its outcome method and every outcome is possible (_switch_mixture_block, switching.md §12). A plate of ExpectationPropagationRule() nodes is grouped too: _group_plan records the rows of the targets’ cavities, and on blocks the group computes the message block, the cavity block (the combine of those rows, as excluded_marginal), and ep_block: a mixture block times a shared-precision Gaussian cavity, projected per replica and divided, gives one GaussianBlock of sites with a precision per replica; other blocks go column by column through ep_message. When any column’s update would be skipped, a variable is pinned, or an input has a negative direction, the group takes the per-edge path, which skips exactly those. EP groups never take the vector-batched path of belief propagation, which would send unprojected messages.

test/plates.jl (“Mixture blocks”): a plate sending its mixtures back to observed points and one whose latent variable pools a Gaussian prior with the mixture (the cavity is then a mixture block times a Gaussian block) give the sequential schedule’s messages to 10−10, with mixture blocks in both directions; the block product equals the per-column combine to 10−12 for proper and improper components, in both orders. The EP plate of “Plates of switching factors on message blocks” now runs on blocks (a site block with per-replica precisions is asserted) and still matches the sequential schedule to 10−10 after 30 sweeps.

What it does not do

  • A mixture block needs one precision for every component and replica, and every outcome possible in every replica (an impossible one is dropped from that replica’s mixture, so the replicas would differ in K); otherwise mixtures are VectorBlocks, computed per replica.
  • Mixture times mixture (K2 components) is column by column.
  • EP sites have a precision per replica; LinearConstraintFactor’s block method takes them (and points) in one loop, but inputs with flat directions per replica go one by one.
  • MixtureReduction(M) nodes take the per-edge path: their component counts differ between replicas.
  • Per-replica precisions (Λ as a vector) are combined and compared column by column; no factor method produces or consumes them in batch, so they take the per-replica fallback inside LinearConstraintFactor.
  • Improper Gaussian inputs with flat directions other than all of Rd take the per-replica path.
  • The AD paths through inference (adjoint = :implicit, non-diagonal couplings) replay on stores without rows, so they are not batched.
  • The validity checks of the free energy (edge directions, tied state) still visit every node; at N=1000 they are most of the remaining 1.1 ms.

Difficulties

  1. A constructor that called itself. MessageStore takes vectors or EdgeMessages, and an outer method on AbstractVector matched EdgeMessages too, so it recursed. The struct has an inner constructor on EdgeMessages, which is more specific.
  2. What cost the time after the first version. The first block sweep took 0.24 ms at N=1000; per group, the costs were small per-replica loops over abstractly typed fields: a pin check per member (an empty-pin shortcut), a detach check per member (moved into the plan), repeat of a short vector (a broadcast into similar), and the residual’s temporaries. The free energy at first sped up 4 times only: a row check called findfirst per member (quadratic), the plate records are a Vector{Any} so the row loops were dynamically typed (function barriers), and scalarisation(f.factor) was dispatched per node (a typed row sum).
  3. Zygote differentiates through a store built from vectors. The coupled drivers build MessageStore(tv, tf, iteration) inside AD (_functional_infer), which used to hold the vectors directly and now wraps them in EdgeMessages. Zygote had no adjoint for the wrapper (the LP-011 tests in gradient_couplings.jl caught it), and its row detection called sum(...; init), which has no rule. The ChainRulesCore extension gives EdgeMessages(v) an rrule that passes the wrapped vector’s tangent through, and marks _energy_rows and _has_rows non-differentiable (they are structural, like the other graph queries there).
  4. Batched beliefs typed Float64 (found in review, 2026-11-03, switching.md §11). FrozenGaussianBeliefs stored its entropy as a Float64, so the scalar free energy on blocks could not be differentiated in ps by ForwardDiff, though the per-edge path could and the tests only differentiated free_energy_gradient’s items (built outside AD). The fields are parametric now, and test/plates.jl differentiates the free energy on blocks.
  5. A loop that was slower than the broadcasts it replaced. The first ep_block took 3.1 ms per sweep at N=1000, most of it in the per-replica moment loop; rewriting the loop without temporaries made it 4.4 ms. The block returned by combine_blocks is not concretely inferred, so every access in the loop was dynamic. A function barrier (_ep_sites) brought it to 0.85 ms.
