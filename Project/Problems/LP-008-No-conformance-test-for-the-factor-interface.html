LP 008 No conformance test for the factor interface

LP-008 No conformance test for the factor interface

27 Oct 202612 min read

  • open-problem

open-problem

Status: resolved (2026-10-27), for the declared exact, approximate-message and deliberately non-game domains below. The 2026-10-23 resolution named a function that did not exist. Related: L-SPEC-001 The Factor Interface, GitHub issue #8.

Sources: original to this vault; code: test/factor_conformance.jl, test/game_composition.jl, test/conformance_capture.jl; package test/conformance.jl files; lib/Adversarial.jl/test/transport.jl, lib/AlgebraicFactors.jl/test/game_exact.jl, lib/VariationalDiffusion.jl/test/bound.jl.

Theory (CT-ML wiki): Statistical Game · Bayesian Lens.

Problem. The factor interface is tested factor by factor. Issue #8 was a mismatch between two parts of the contract (scalarisation and energy) that no test covered, because each factor’s tests exercised only the paths it used. Other factor types (the diffusion, equilibrium, neural-ODE and adversarial factors) may have similar gaps.

Options.

  1. A conformance test: a function check_factor(f, ps, st, samples) in a test utility that runs every applicable part of L-SPEC-001 The Factor Interface (§1–§5) and the consistency conditions between them, called from each package’s tests for each factor type.
  2. Keep per-factor tests and add the cross-checks by hand.

Resolution through 2026-10-25 (history). The review-argon commits claimed option 1 (check_factor_conformance) but only added a loop over traits; the function did not exist (LP-013 Defects found in the review of master). Since bb3af9e9 it does, in test/factor_conformance.jl: for a factor and polarity it checks the testable parts of L-SPEC-001 The Factor Interface §1–§5 (traits, invert = combine(π, likelihood_message), the pointwise energy and its scalarisation, game-level free_energy and entropy in energyspace). It runs over every supported polarity of GaussianFactor, GaussianPrior, LinearConstraintFactor, NonlinearFactor and LikelihoodFactor (297 checks). Since 2026-10-25 the checker also has a direct-message path (direct_message = true, with independently computed site and posterior fixtures) for factors that implement factor_message without a lens; AlgebraicFactors.ToricFactor runs through it over every supported polarity at arities one to three. Open as of 2026-10-25: the factors of Mycelium, ImplicitLayers, VariationalDiffusion and Adversarial are not run through it yet.

2026-10-27: exact-domain conformance and complete subtype audit

This section supersedes the 2026-10-26 rollout table and its remaining-work list. LP-009 Game-level free energy is declared but not implemented supplies the agreed bounds-plus-exact-cases semantics; the common checker now exercises each implemented exact domain without inventing a density, posterior entropy or wiring convention.

The default scope=:wired retains all existing checks and opt-out defaults. Independent expected_free_energy and expected_entropy fixtures additionally compare individual energy coordinates; wired runs also compare graph free energy with the expected value. Gaussian distributional observations already fit game_y, so they need no special-case factor dispatch. scope=:game checks parameters/states, game spaces, entropy/free-energy coordinates and default/custom scalarisation, requiring both independent fixtures. It makes no channel, pointwise, inversion or graph claim. scope=:bound requires full evidence, API keyword arguments and an independently computed finite exact negative log evidence; it checks an evaluated FreeEnergyUpperBound, finiteness, rejection by scalarise, and bound.value >= exact - 1e-10 (roundoff only). A sampled estimate cannot satisfy the type check. Neither scope silently substitutes for a wired sink: both explicitly use p=nothing.

The Gaussian composition sites/posteriors now come from matrix Gaussian multiplication, rather than the collapsed implementation’s lens. Game fixtures use residual covariance and Gaussian entropy, including the full joint posterior for soft observations. Tensor fixtures check every nested branch, with GaussianFactor, GaussianPrior, collapsed pair and independent product components. Polynomial fixtures use scalar Gaussian conditioning for all four Dirac/Gaussian input/output pairs, in addition to both wired polarities, row gauges, bases and damping. Plucker checks both placements of the Gaussian input. Transport fixtures use the affine output covariance and standard-normal entropy. Diffusion fixtures propagate the finite reverse chain’s mean and variance independently, including stationary equality, displaced-score strict gaps and nonstationary variances. Negative checker tests reject a graded fixture with cancelling coordinate errors and a falsely increased exact NLL; captured intentional failures are asserted, not counted as suite passes.

Audit command (run from the repository root, excluding local working material):

The grep found 22 production types and eight test-only types (including multiline supertype declarations and the container subtype). There are no concrete wrapper-factor subtypes. Every match is accounted for above. The previous table omitted the five top-level factors and ToricFactor; those omissions are corrected here.

Remaining scope, deliberately excluded: general ratio/reweighted entropy, nonlinear transport exact expectations, singular or non-Gaussian Plucker images, nonlinear/multiple polynomial branches, arbitrary/nested composition laws, tensor graph wiring/correlated beliefs, and exact diffusion prox/posterior games or partial-evidence bounds. These are the explicit semantic boundaries agreed in LP-009, rather than implemented APIs awaiting checker coverage. All implemented new exact domains now reach the common checker. Existing callers had no obsolete game/message keyword exemptions for those domains; the obsolete exemptions were the historical rollout claims. The only real game/message opt-outs left are Optimiser’s non-game, Loss’s terminal message and the diffusion surrogate game, with their reasons above. LP-008 is therefore resolved; extending those semantics would require new laws and fixtures, not removal of an unexplained checker exemption.

This is the least invasive reuse: test environments already have its libraries; Mycelium’s test project only needs direct LuxCore/Random visibility. Defaults retain all checks, and game/graph agreement now compares every energy coordinate, not just their scalar sum. Independent site/posterior fixtures also work on the default lens path.
