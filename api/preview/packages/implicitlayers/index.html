ImplicitLayers

SciML's implicit layers — deep equilibrium networks and neural ODEs — as factors.

There is no hard SciML dependency: neither DeepEquilibriumNetworks.jl nor DiffEqFlux.jl is required, because what these wrappers need is the inner Lux network, not the assembled layer.

Three wrappers, and the difference matters

wrapperyou supplypolarities
LuxFactorthe assembled DeepEquilibriumNetwork / NeuralODE1
DEQFactorthe cell $g_\theta(z,x)$2, if the residual is square
NeuralODEFactorthe dynamics $f_\theta(z,t)$2, always

LuxFactor works today on anything in the SciML ecosystem and asks nothing of it. It gives you graph membership, parameter management and free-energy accounting — and one direction, because a Lux layer has already chosen which side is the input.

The other two keep the relation instead of the solved function, and get both directions:

# a DEQ: keep the residual r(x,z) = z - g(z,x)
f = DEQFactor(my_cell, (x = 4, z = 4); solver = BroydenSolver())
solve_state(f, x, ps, st)     # solve for z  — what SciML's DEQ does
solve_input(f, z, ps, st)     # solve for x  — what it cannot be asked

The reverse solve needs $\dim x = \dim z$; otherwise the residual is not square and supports_polarity refuses that direction rather than solving it badly.

Optional automatic differentiation

Load DifferentiationInterface, ADTypes and your backend package. For a DEQ solve, pass ad=AutoForwardDiff(), AutoZygote(), AutoEnzyme() or AutoMooncake() to solve_state or solve_input. Load ForwardDiff as well for the EnzymeCore/Mooncake extensions. The weak extensions implement the IFT, without differentiating root-finder iterations. Both input and parameter derivatives are tested against the linear-cell closed form and finite differences. Root convergence is required; singular residual Jacobians throw. Both solve polarities have first-order rules. Lux state is fixed throughout an AD root solve and advances once at the final root. Solve reports, initial guesses and state have no tangent.

deq_sensitivity(...; wrt=:ps, ad) gives the dense parameter sensitivity directly. DEQFactor(...; ift=DenseIFT()) defaults to dense LU. To use matrix-free IFT rules, load Krylov and select ift=KrylovIFT(rtol=1e-10, atol=1e-12, itmax=400, memory=20, precond=JacobiIFT()). Restarted GMRES uses only residual JVPs (forward) or VJPs (reverse). It throws on nonconvergence and checks the final residual explicitly. Krylov.jl provides the operator-product interface directly, without another operator package. All four backends are checked against the linear exact solution, including a 200-dimensional contractive example that forbids the dense state-Jacobian API. deq_sensitivity stays dense. The native Enzyme/Mooncake rules keep their existing inner ForwardDiff path in dense mode; in Krylov reverse mode each uses its own reverse backend. GPU remains untested. Dedicated dense second-order products are described below. Enzyme outer closures capturing arrays need DI constant contexts or AutoEnzyme(function_annotation=Enzyme.Const); see solve.md for a reproducer.

Core's energy_jacobian(...; wrt=:ps, ad), energy_gradient and free_energy_gradient apply to DEQ, NeuralODE and scored Lux factors. Built-in Euler/RK4 endpoint flows use functional Lux state threading and differentiate the discrete map with ForwardDiff, Zygote, Mooncake and Enzyme. For Enzyme, pass AutoEnzyme(; mode = Enzyme.set_runtime_activity(Enzyme.Reverse)) (or Forward): constant model/stage memory flows through an active fold, requiring runtime activity. The factor derivative and graph training entry points check the mode before AD and raise an ArgumentError with that configuration when it is missing. Arbitrary outer DI calls must select it themselves. Plain AutoEnzyme() works for DEQ and scored LuxFactor paths. The ODE activity check does not require ForwardDiff; DEQ IFT does. neuralode.md describes the activity requirement. Tests derive both scalar discrete derivatives, check nonempty Lux state and fit a known ODE parameter using Mycelium's graph parameter_step. LuxFactor(...; dims=(nin,nout), residual=true) opts into squared endpoint-residual scoring; the default wrapper still delegates energy to downstream losses.

Preconditioning and second order

KrylovIFT(precond=M) uses a left operator. A factory precond=ctx -> (; left=M, right=N) can construct either side from the current problem; ctx.transposed distinguishes reverse solves. Omitted sides are identity. The default ldiv=false applies mul! with approximate inverses; ldiv=true applies ldiv!. Operators follow Krylov.jl's protocol. JacobiIFT() supplies an inverse diagonal using n operator probes and O(n) storage; small/nonfinite diagonal entries throw. on_solve=r -> ... receives a named tuple with iterations, residual and solved for each RHS. The final original residual is checked even with preconditioning. The built-in inverse requires ldiv=false.

using ForwardDiff, DifferentiationInterface, ADTypes
hv = deq_hvp(z -> sum(abs2,z)/2, f, x, ps, st, v;
             wrt=:ps, ad=AutoForwardDiff())

This dedicated second-order adjoint computes a flat Hessian-vector product of loss(zstar) using dense residual and loss derivatives, without differentiating root iterations. wrt=:x selects inputs; :joint selects input followed by flattened parameters and includes mixed blocks. The loss may depend on input and parameters only through the solved state. Only DenseIFT(), CPU real floating point arrays and AutoForwardDiff() are supported. Storage is quadratic in the combined state/input/parameter dimension. Unsupported backend selections raise ArgumentError; arbitrary nesting of the first-order solve rules is unsupported. The tests compare linear products to the closed-form solve, nonlinear scalar second derivatives, and finite differences of first-order IFT gradients.

The no-AD solve_input retains legacy state threading. Its AD path holds incoming state fixed and advances it once at the root; stateful cells can therefore produce different roots in these two paths. Warm starts have zero derivative in both solve polarities' AD rules. Square dimensions alone do not guarantee a nonsingular root.

Neural ODE endpoint integration

The continuous flow has an inverse wherever solutions exist uniquely in both directions. Numerical reverse integration approximates that inverse; Euler/RK4 do not invert their discrete forward map, even in exact arithmetic. Both endpoint polarities are supported:

f = NeuralODEFactor(my_net, 4; tspan=(0.0,1.0), integrator=RK4Integrator())
flow_forward(f, z₀, ps, st)
flow_reverse(f, z₁, ps, st)
flow_logdet(f, z₀, ps, st)

RK4Integrator(steps=50) remains the default. Euler's round-trip error is $O(h)$. RK4 has fourth-order forward error and an $O(h^4)$ round-trip bound for smooth dynamics; the scalar linear round trip is sharper, $O(h^5)$. Its doubling ratio is 32, while the forward-error ratio is 16. lib/ImplicitLayers.jl/examples/flow_roundtrip.jl reproduces the table in the implementation note: at $a=-5,T=1,N=50$, Euler's residual is 0.394994 with a 20.9% start-point error, RK4's is $6.953127\times10^{-7}$. At $N=1$ RK4's is 895.18. Inverting a contracting flow separately amplifies absolute endpoint perturbations by $e^{|a|T}$; a better integrator cannot remove this conditioning.

Optional OrdinaryDiffEq extension

Install the solver subpackages, then load them with ImplicitLayers:

using ImplicitLayers, OrdinaryDiffEqCore, OrdinaryDiffEqTsit5, OrdinaryDiffEqSDIRK
adaptive = SciMLIntegrator(Tsit5(); reltol=1e-9, abstol=1e-12)
fixed = SciMLIntegrator(ImplicitMidpoint(); adaptive=false, dt=0.02,
                       reltol=1e-12, abstol=1e-12)
f = NeuralODEFactor(my_net, 4; integrator=fixed)

Core/SciMLBase supply the solve interface; Tsit5 and SDIRK supply the selected algorithms. These are weak dependencies, so the full OrdinaryDiffEq umbrella and its other solvers are unnecessary. The test environment resolves Core 4.19.0, Tsit5 2.1.5 and SDIRK 2.9.8.

The extension solves an out-of-place ODEProblem over either time direction and returns only the final state. It signs positive dt automatically, disables intermediate storage, and rejects failed/incomplete solves. CNF divergence is a finite-difference trace integrated as an augmented state; the built-in quadrature is unchanged. Lux state is threaded through every RHS evaluation, including rejected stages and divergence probes.

inversion_kind gives Euler/RK4 and adaptive Tsit5 SolverInversion(integrator). Midpoint and Trapezoid are symmetric methods (Hairer–Lubich–Wanner II.3); with adaptive=false, matching grids (dt divides the interval), a default step limiter, and only dt, adaptive, abstol, reltol, maxiters options, the trait permits ExactInversion up to nonlinear-solve tolerance and roundoff. assemble also requires empty Lux state. This describes the discrete inverse, not exactness against the continuous ODE. Tests use abstol=reltol=1e-12 and check relative round-trip residual below $10^{-10}$.

Load SciMLSensitivity to enable SciML endpoint parameter AD:

using SciMLSensitivity, OrdinaryDiffEqTsit5
itg = SciMLIntegrator(Tsit5(); abstol=1e-12, reltol=1e-10)
# Optional continuous adjoint:
adjoint_itg = SciMLIntegrator(Tsit5(); abstol=1e-12, reltol=1e-10,
    sensealg=GaussAdjoint(autojacvec=ZygoteVJP()))
f = NeuralODEFactor(my_net, 4; integrator=itg)
J = energy_jacobian(f, z0, nothing, y, ps, st; wrt=:ps, ad=AutoZygote())

The default sensealg=nothing resolves to ForwardDiffSensitivity() for small parameter counts, as recommended by the SciMLSensitivity manual. Flattened Lux parameters are passed as ODEProblem.p, with a zero-valued shape template in the RHS. The sensitivity path requires recursively empty incoming and returned Lux state. Nonempty incoming state falls back to legacy evaluation-state threading for primal forward/reverse flows and inference. Factor and graph derivative entry points reject AD with nonempty state before tracing; reference differences remain available. This excludes mutable statistics whose evolution depends on adaptive/rejected stages. An arbitrary outer DI call bypasses the factor/graph check, so its caller must enforce the empty-state restriction, as with Enzyme runtime activity. Euler/RK4 state threading is unchanged.

Tsit5 tests cover AutoForwardDiff (dual solves), AutoZygote and AutoMooncake with the default, InterpolatingAdjoint and GaussAdjoint (both with ZygoteVJP()). They compare with $D_a z(T)=Tz_0e^{aT}$ and nonlinear finite differences; graph parameter_step learns the continuous-time target $e^{0.4}$ with the default. Factor/graph derivative entry points explicitly reject AutoEnzyme on this SciML path. Sensitivity selection leaves inversion labels and reversal semantics unchanged. CNF/divergence AD, other solvers, callbacks, GPU and higher derivatives are untested. Continuous adjoints can retain intermediate trajectories internally. Backsolve reverse-conditioning concerns still apply.

Solvers

PicardSolver is the naive "keep applying the layer" loop and converges only if the iteration is a contraction. BroydenSolver is derivative-free quasi-Newton and converges on plenty of problems where Picard diverges — it is the default, and it is what DeepEquilibriumNetworks.jl reaches for too.

LimitedBroydenSolver(memory=20) opts into good inverse Broyden with at most 20 rank-one corrections, O(memory*n) storage and work, and no dense inverse. With no eviction its iterates agree with dense Broyden up to roundoff. The first step is Picard for init_scale=1, damped Picard otherwise. Dropping old corrections can slow convergence; there is no line search.

All root solvers return a SolveReport (converged, iterations, residual, function evaluations) rather than throwing. A solver that stopped early is an inexact inversion, which is legal.

ift_sensitivity implements the implicit function theorem, $\partial z^\ast/\partial x = (I - \partial_z g)^{-1}\partial_x g$ — one linear solve, no unrolling.

Known gaps

  • Dense IFT remains the default. Jacobi setup requires one operator probe per coordinate.
  • SciML coverage is limited to the tested Tsit5 endpoint algorithms above; divergence AD and nonempty-state sensitivities are not covered.
  • Second-order IFT is limited to the dedicated dense forward-polarity adjoint above.
  • Built-in explicit methods have no error estimate and may diverge on coarse or stiff problems. The optional solvers do not remove inverse conditioning or establish GPU support.
  • Every inversion returns a DiracBelief.

ImplicitLayers.ImplicitLayers — Module
ImplicitLayers

SciML's implicit layers — deep equilibrium networks and neural ODEs — as Lenticulum factors. The equilibrium family of Implicit Learners.md, alongside VariationalDiffusion.jl's diffusion family.

The thesis

DeepEquilibriumNetworks.jl and DiffEqFlux.jl both hand you an AbstractLuxLayer: a function $x \mapsto y$ whose direction is fixed when you construct it. But both are built out of a relation —

\[\text{DEQ:}\quad z = g_\theta(z,x) \qquad\qquad \text{NeuralODE:}\quad \frac{dz}{dt} = f_\theta(z,t)\]

— and the layer is that relation with one direction chosen and the solve sealed inside. So there are two ways to wrap them, and the difference is the whole point of this package:

wrapperwhat you give itpolaritieswhat you get
LuxFactorthe assembled DeepEquilibriumNetwork / NeuralODE1graph membership; a Lux layer with extra steps
DEQFactorthe cell $g_\theta$2 (if square)the relation; solvable for either channel
NeuralODEFactorthe dynamics $f_\theta$2, alwaysboth endpoint integrations; exactness depends on method

LuxFactor works today on anything in the SciML ecosystem and asks nothing of it. The other two need the inner network rather than the assembled layer, and give back the bidirectionality the rest of the project is about.

The files

filenotesupplies
solve.jl[[solve]]Picard, dense/limited Broyden, SolveReport, preconditioned IFT
deq.jl[[deq]]DEQFactor — both solve polarities, first-order AD and dense HVP

Concept notes: [[The Equilibrium Family]], [[DEQ as a Relation]], [[NeuralODE as an Invertible Factor]].

Two properties worth knowing up front

No hard SciML dependency. Built-in root solvers and Euler/RK4 work without SciML. Optional SciMLIntegrator uses OrdinaryDiffEqCore/SciMLBase and solver subpackages such as OrdinaryDiffEqTsit5 and OrdinaryDiffEqSDIRK. Explicit time reversal only approximates the inverse of the numerical forward map; symmetric fixed-step methods on matching grids can invert it up to nonlinear-solve tolerance. See inversion_kind. Optional DI derivatives accept a user-selected ADTypes backend. DEQ solves have IFT rules in weak ChainRulesCore, ForwardDiff, EnzymeCore and Mooncake extensions. Euler/RK4 endpoint flows use functional state threading with ForwardDiff, Zygote and Mooncake, plus Enzyme with runtime activity enabled, for example AutoEnzyme(; mode = Enzyme.set_runtime_activity(Enzyme.Reverse)) (or Forward). Plain AutoEnzyme() remains supported for DEQ and scored LuxFactor paths. Loading SciMLSensitivity enables SciML endpoint derivatives with ForwardDiff/Zygote/Mooncake and recursively empty Lux state. DEQFactor(...; ift=KrylovIFT()) opts into matrix-free first-order solves via the Krylov weak extension. Base derivative tools use finite differences and remain small-system tools; see solve.md §4.

Every inversion returns a DiracBelief. A root-find and an ODE solve both produce a point. GaussianBelief is now in LenticulumCore, so a Gaussian answer (a covariance pushed through deq_sensitivity) is possible but not built yet. See [[The Equilibrium Family]] §5.

ImplicitLayers.AbstractRootSolver — Type
abstract type AbstractRootSolver

A method for solving $F(u) = 0$ given only the ability to evaluate $F$.

Derivative-freeness is a requirement, not a convenience: the residual of a DEQ contains a neural network, and this package has no automatic-differentiation dependency (see ImplicitLayers.md). It is also what DeepEquilibriumNetworks.jl does in practice — Broyden and limited-memory Broyden are its workhorses.

source
ImplicitLayers.BroydenSolver — Type
BroydenSolver(; maxiters = 100, tol = 1e-10, init_scale = 1.0)

"Good" Broyden: a quasi-Newton method maintaining an approximate inverse Jacobian updated by the Sherman–Morrison formula from secant pairs.

Derivative-free, and it is what DeepEquilibriumNetworks.jl reaches for. Note the initialisation: with $H_0 = I$ the first step is

\[u_1 = u_0 - H_0F(u_0) = u_0 - (u_0 - g(u_0)) = g(u_0)\]

— the first Broyden step is exactly a Picard step, and everything after it is the correction Picard never makes. Asserted in the test suite.

Stores a dense $n\times n$ matrix, so it is $O(n^2)$ in memory. Real DEQs use limited-memory Broyden for exactly this reason; see solve.md §4.2.

ImplicitLayers.DEQFactor — Type
DEQFactor(cell, dims::NamedTuple; solver = BroydenSolver(), channels = (:x, :z),
          input = default_cell_input, ift = DenseIFT())

A deep equilibrium model as a relation: the fixed-point condition $z = g_\theta(z, x)$ presented as a residual, solvable for either channel.

cell is any LuxCore.AbstractLuxLayer computing $g_\theta(z,x)$ — including a DeepEquilibriumNetworks.jl cell, which is exactly such a layer. dims gives the two channel dimensions. Parameters and state are the cell's, untouched. ift=KrylovIFT() opts into matrix-free GMRES in solved-state AD rules (load Krylov and DI); dense LU is the default.

f = DEQFactor(my_cell, (x = 4, z = 4); solver = BroydenSolver(maxiters = 200))
The reverse direction needs a square system

Solving $z = g(z,x)$ for x is $\dim z$ equations in $\dim x$ unknowns. Unless $\dim x = \dim z$ it is over- or under-determined and the root solve is not asking a well-posed question. LenticulumCore.supports_polarity refuses that polarity rather than solving it badly; see deq.md §3.

Contrast LuxFactor, which wraps an already assembled DeepEquilibriumNetwork and gets one polarity — a Lux layer with extra steps.

JacobiIFT(; min_diagonal=1e-14)

Opt-in KrylovIFT(precond=JacobiIFT()) inverse diagonal preconditioner. Uses n operator probes and O(n) storage, without forming the state Jacobian. Rejects nonfinite or small diagonal entries. Uses mul! (ldiv=false).

source
ImplicitLayers.KrylovIFT — Type
KrylovIFT(; rtol=1e-10, atol=1e-12, itmax=0, memory=20,
           precond=nothing, ldiv=false, on_solve=nothing)

Opt-in matrix-free GMRES IFT solve. Load Krylov and DifferentiationInterface. itmax=0 uses Krylov's default (twice the state dimension). Restart after memory iterations to bound basis storage. Failure to meet the residual tolerance throws.

precond accepts a left operator or a factory ctx -> (; left=M, right=N); omitted sides are identity. ctx contains operator, transposed, factor, solved (channel name), joint (observed channel followed by parameters), root, template, offsets and state. Build preconditioners for the indicated orientation. Krylov applies mul! by default (operators approximate the inverse); ldiv=true applies ldiv! instead. JacobiIFT() probes the operator diagonal. on_solve, when supplied, receives (iterations, residual, solved) as a named tuple after each linear solve, including failures; residual is measured in the original, unpreconditioned system.

source
ImplicitLayers.LimitedBroydenSolver — Type
LimitedBroydenSolver(; memory=20, maxiters=100, tol=1e-10, init_scale=1.0)

Good inverse Broyden with at most memory rank-one secant corrections to init_scale*I. Stores two vectors per correction, never a dense inverse: O(memory*n) storage and work per step. Evicts the oldest correction without rebuilding the others. With no eviction, reproduces dense Broyden up to roundoff. The first step is damped Picard with damping init_scale (ordinary Picard when it is one).

ImplicitLayers.LuxFactor — Type
LuxFactor(layer, :in => :out; dims = (nothing, nothing), postprocess = identity, residual = false)

Any LuxCore.AbstractLuxLayer as a unidirectional factor.

The point of least resistance for reusing the SciML ecosystem: a DeepEquilibriumNetwork, a NeuralODE, a Chain, a Boltz vision backbone all satisfy the interface, so all of them wrap without this package knowing anything about them.

postprocess adapts the layer's output to a plain array — needed for the SciML layers whose call returns a solution object rather than a vector:

# DiffEqFlux's NeuralODE returns an ODESolution
LuxFactor(NeuralODE(net, (0.0, 1.0), Tsit5()), :x => :y;
          postprocess = sol -> Array(sol)[:, end])

# DeepEquilibriumNetworks returns the steady state directly, and reports the solve in `st`
LuxFactor(DeepEquilibriumNetwork(cell, NewtonRaphson()), :x => :z)

Set residual=true (with an explicit output dimension in dims) to score the endpoint vector y - layer(x) with a squared norm. Core parameter derivatives and Mycelium's fixed-message parameter_step can then train this factor. The default keeps zero energy for compatibility with downstream-loss graphs. Direct losses on apply_layer can also be differentiated with LenticulumCore.parameter_gradient.

One polarity, by construction

isunidirectional(::LuxFactor) == true. A Lux layer is a lens ([[Lux as a Parametric Lens]]); a factor only becomes one once a polarity is chosen, and a layer has already chosen. So this wrapper buys graph membership, parameter management and free-energy accounting — and none of the bidirectionality the rest of the project is about. Use it when the model genuinely is a function; use DEQFactor or NeuralODEFactor when it is not.

ImplicitLayers.NeuralODEFactor — Type
NeuralODEFactor(dynamics, dim; tspan = (0.0, 1.0), integrator = RK4Integrator(),
                channels = (:z0, :z1), input = default_dynamics_input)

A neural ODE as a bidirectional factor: the relation $\{(z_0,z_1) : z_1 = \Phi_{t_0\to t_1}(z_0)\}$ where $\Phi$ is the flow of $dz/dt = f_\theta(z,t)$.

dynamics is any LuxCore.AbstractLuxLayer computing $f_\theta(z,t)$ — the same object you would hand to DiffEqFlux.NeuralODE. Parameters and state are its own.

f = NeuralODEFactor(my_net, 4; tspan = (0.0, 1.0), integrator = RK4Integrator(steps = 100))

Both channels have dimension dim — a flow cannot change the dimension of its state, which is why this factor takes one dim rather than two and why a NeuralODE cannot be used as an encoder that compresses. Contrast DEQFactor, whose two channels are independent.

Compared to DiffEqFlux.NeuralODE

NeuralODE(model, tspan, Tsit5()) is a Lux layer: (n)(x, ps, st) builds an ODEProblem and returns (ODESolution, st). Direction fixed at construction, output a solution object. Wrapping that gives you LuxFactor and one polarity; this factor keeps the flow and gets two.

NeuralODEModel(factor, polarity)

ImplicitLayers.PicardSolver — Type
PicardSolver(; maxiters = 100, tol = 1e-10, damping = 1.0)

Damped fixed-point iteration $u \leftarrow u - \beta F(u)$.

For the DEQ residual $F(z) = z - g(z,x)$ this is exactly $z \leftarrow (1-\beta)z + \beta g(z,x)$: the naive "just keep applying the layer" loop.

A contraction is sufficient for convergence, and nothing checks that in advance; it is not a necessary condition for a particular initial guess. That is the caveat Implicit Learners.md records — "this only works if the iteration converges, and unconstrained DEQs need not" — and the test suite exhibits a linear cell with spectral radius > 1 on which this solver diverges and BroydenSolver does not.

ImplicitLayers.RK4Integrator — Type
RK4Integrator(steps = 50)

Classical fourth-order Runge–Kutta, fixed step. The default: for the smooth non-stiff dynamics a NeuralODE usually has, steps = 50 of RK4 is far more accurate than anything Euler reaches, and it is Tsit5's spiritual ancestor without the adaptivity.

ImplicitLayers.SciMLIntegrator — Type
SciMLIntegrator(alg; sensealg = nothing, kwargs...)

Optional OrdinaryDiffEq solver, loaded by using OrdinaryDiffEqCore and a solver package (e.g. OrdinaryDiffEqTsit5 or OrdinaryDiffEqSDIRK). Keywords go to solve; only the final state is retained. dt is a positive magnitude, signed automatically for reverse solves.

Fixed-step ImplicitMidpoint/Trapezoid can invert their discrete map up to nonlinear-solve tolerance; adaptive solvers such as Tsit5 only control integration error. See inversion_kind for the conservative exactness conditions. Loading SciMLSensitivity enables endpoint parameter derivatives with recursively empty Lux state. sensealg=nothing selects ForwardDiffSensitivity() for small problems; pass an explicit adjoint to override it. Sensitivity options do not affect inversion labels.

source
ImplicitLayers.SolveReport — Type
SolveReport(converged, iterations, residual, nfe)

What a root solve is willing to say about itself.

nfe (number of function evaluations) is reported because it is the honest cost measure for an implicit layer — DeepEquilibriumNetworks.jl reports it too, in its DeepEquilibriumSolution, for the same reason: iteration count means nothing when one Broyden step and one Picard step cost differently.

[!important] converged == false is not an error Bayesian Lens.md: a solver that stopped early is an inexact inversion, and inexact inversions are legal — the free energy records the cost. So the report is threaded out rather than thrown, and it is the caller's business what to do about it.

ImplicitLayers.flow_logdet — Method
flow_logdet(f, z₀, ps, st) -> (z₁, Δlogdet, st)

Forward flow together with $\int \operatorname{tr}\partial_z f_\theta\,dt$, so that

\[\log p(z_1) = \log p(z_0) - \Delta\!\log\!\det\]

the instantaneous change of variables. This is the piece that would make the factor transport a density rather than a point. It is not used for that yet: GaussianBelief is now reachable (in LenticulumCore), but a flow needs a non-Gaussian, pushforward belief, which does not exist. See neuralode.md §4.2.

ImplicitLayers.ift_sensitivity — Method
ift_sensitivity(Jz, Jx) -> Matrix

The implicit function theorem, applied to a fixed point $z^\ast = g(z^\ast, x)$:

\[(I - \partial_z g)\,\frac{\partial z^\ast}{\partial x} = \partial_x g \qquad\Longrightarrow\qquad \frac{\partial z^\ast}{\partial x} = (I - \partial_z g)^{-1}\,\partial_x g\]

One linear solve, no unrolling — storage independent of the root iteration count (the dense state Jacobian still takes quadratic storage), and the reason Implicit Learners.md lists the IFT as the equilibrium family's backward pass. See [[Backpropagation by the Implicit Function Theorem]].

Throws if $I - \partial_z g$ is singular: the IFT does not establish a locally differentiable inverse there. This alone does not imply nonuniqueness (a cubic residual can have a unique root with zero derivative). Dense matrix reference only.

ImplicitLayers.integrate — Method
integrate(vf, u₀, t₀, t₁, integrator) -> u₁

Integrate $du/dt = \mathrm{vf}(u, t)$ from t₀ to t₁.

t₁ < t₀ is allowed and is the whole point: dt is simply negative and the same scheme runs backwards. vf is called as vf(u, t).

source
ImplicitLayers.integrate_with_divergence — Method
integrate_with_divergence(vf, u₀, t₀, t₁, integrator) -> (u₁, Δlogdet)

Integrate the state and the log-density correction of a continuous normalising flow:

\[\frac{d}{dt}\log p(u(t)) = -\operatorname{tr}\frac{\partial \mathrm{vf}}{\partial u} \qquad\Longrightarrow\qquad \log p(u_1) = \log p(u_0) - \underbrace{\int_{t_0}^{t_1}\!\operatorname{tr}\,\partial_u \mathrm{vf}\,dt}_{\texttt{Δlogdet}}\]

This is the instantaneous change-of-variables of Chen et al. / FFJORD, and it is what turns a NeuralODE from a map on points into a map on densities — i.e. what would let this factor push a real belief rather than a Dirac.

[!warning] The trace is computed by a dense finite-difference Jacobian $O(n)$ extra evaluations of vf per divergence evaluation. Built-in methods use trapezoidal quadrature; SciML integrates an augmented state. FFJORD's Hutchinson estimator avoids the dense trace; see flow.md §4.1. What is here is correct, checkable against a linear system, and unusable above small n.

ImplicitLayers.solve_input — Method
solve_input(f, z, ps, st; x₀, ad=nothing) -> (x★, SolveReport, st)

Solve $z = g_\theta(z, x)$ for x, holding z fixed — the direction a DeepEquilibriumNetwork cannot be asked for.

Requires $\dim x = \dim z$. Even then it is a general nonlinear root-find in x with no contraction structure to lean on, so Broyden is the only sensible solver and convergence is a genuinely open question per call. That is why the SolveReport is returned rather than discarded.

ImplicitLayers.solve_state — Method
solve_state(f, x, ps, st; z₀, ad = nothing) -> (z★, SolveReport, st)

Solve $z = g_\theta(z, x)$ for z. The forward DEQ pass — what DeepEquilibriumNetworks.jl does.

LenticulumCore.free_energy — Method
LenticulumCore.free_energy(lens, π, inputs, ps, st)

For an assembled DEQ/NeuralODE lens, evaluate the residual energy at invert's point, then add the prior's anchor cost on the unobserved channel. inputs is a Dirac observation or a NamedTuple containing that observation on the polarity's observed channel.

The anchor is zero for a trivial prior; zero at an exactly equal Dirac point and infinite elsewhere; or ½(u-μ)'Λ(u-μ) for a proper Gaussian. The Gaussian cost is relative to its mean (no log-normalization constant). Channel precisions do not soften a Dirac prior. Soft observations and other beliefs throw. Entropy uses the zero point-belief convention.

This is Definition 20's expectation under the inversion, with this specified residual and anchor energy. assemble(f, p) restricts the relation to one polarity; it does not turn the root/flow inversion into a posterior conditioned on the anchor. See point_game.md.

Game quantities and conformance

The default LuxFactor requires a Dirac input observation y and contributes zero game energy and entropy. With residual=true, its game instead scores Dirac endpoints in the first/second channel order, with zero point-belief entropy. DEQFactor and NeuralODEFactor implement two games:

  • free_energy(f, π, y, ps, st) scores incoming Dirac points: π on the first channel (x or start), y on the second (z or end), following GaussianFactor's fixed order. It equals Mycelium.local_free_energy for those messages. Entropy is scalar zero; non-Dirac arguments throw.
  • lens = first(assemble(f, p, ps, st)) restricts the relation to one polarity. free_energy(lens, π, inputs, ps, st) runs that inversion and scores its returned point: residual energy plus an anchor on the unobserved channel. inputs contains a named Dirac observation (or that Dirac directly). A trivial prior costs zero; an incompatible hard Dirac prior costs infinity; a proper Gaussian costs $\tfrac12(u^*-\mu)^\top\Lambda(u^*-\mu)$ relative to its mean, without a normalization constant. The inversion still uses the prior only as a warm start (DEQ), or ignores it (ODE). Soft observations, singular Gaussian anchors and other prior families throw. Channel precision does not soften Dirac priors.

The lens game is Definition 20's expectation under the point inversion, with zero point-belief entropy. Both games return (F, st) in ScalarEnergySpace(); scalar_free_energy also accepts these lenses and a scalarisation override σ. Scoring arbitrary points uses energy/scalar_energy (L-ADR-0003), not a free_energy keyword.

If the residual is affine in the unknown and vanishes at the solved point, the incoming energy equals the solved residual energy plus a Gaussian anchor with precision $J_u^\top J_u$ centered at the incoming unknown. energy_jacobian supplies this metric. The tests derive 1/8 for g(z,x)=z/2+x at x=1,z=3 in both directions, and 2 for zero ODE dynamics at endpoints 1,3 in both directions. A nonlinear quadratic DEQ checks cubic absolute energy error for the first-order Gauss–Newton approximation. The common factor checker now covers the complete point game for both factors without LP-009 exemptions.

Solved-state IFT AD accepts AutoForwardDiff(), AutoZygote(), AutoEnzyme() and AutoMooncake(). Load DI, the backend and (for Enzyme/Mooncake) ForwardDiff; missing extensions and other solve backends are rejected before solving. Pass the backend to solve_state and the outer derivative. Enzyme outer closures that capture arrays need DI constant contexts or function_annotation=Enzyme.Const; see the implementation note solve.md for the limitation and reproducer. GPU remains untested. Second order is limited to the dedicated dense adjoint above.
